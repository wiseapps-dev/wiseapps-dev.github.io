How to format a script so an app can read it

Updated 21 November 2026, by the maker of Scenewise

To format a script so an app can read it, put each character's name in capitals, either before the line with a colon or on its own line above it. Spell each name the same way every time, put stage directions in brackets, and give scene headings their own line. Scanned PDFs are pictures, so they can't be read.

When you read a script, you know at a glance who's speaking, which bits are stage directions and where a new scene starts. An app has to work all of that out from the text alone. Most published scripts and screenplays follow conventions that make this easy. Scripts typed up by a director, pasted from an email, or exported from a scanner sometimes don't.

This guide covers the layouts that work reliably, how to fix the ones that don't, and why scanned PDFs can't be read at all. It's written for Scenewise, but the same rules help with most line-learning apps and with screenwriting formats like Fountain.

The short version

  • Names in capitals, either before the line with a colon, or on their own line above it.
  • The same spelling of each name every time.
  • Stage directions in brackets: (round) or [square].
  • Scene headings on their own line: SCENE 2, ACT ONE, INT. KITCHEN - NIGHT.
  • A text PDF, not a scan. If you can't select the words, an app can't read them.

Rule 1: Put character names in capitals

There are two layouts that work every time. Pick one and use it throughout.

Name and colon, on the same line. Common in plays typed up for rehearsal, and the easiest to type yourself:

NELL: I came back for the piano.

ROSS: And?

NELL: And it still knows the tune.

Name on its own line, speech underneath. The screenplay layout. The Fountain screenwriting format defines a character cue as a line entirely in capitals, with a blank line before it and the dialogue straight after it, with no blank line in between:

NELL
I came back for the piano.

ROSS
And?

Scenewise also reads the style used in many published plays, with a full stop after the name (NELL. I came back for the piano.), and the "NAME, two spaces, speech" style of some online play texts. What matters most is that the script is consistent.

Character extensions like (V.O.), (O.S.) and (CONT'D) after a name are fine. They're recognised and ignored, so "NELL (CONT'D)" is still Nell.

Names that aren't in capitals

If a name has to stay in mixed case, put @ in front of it. That's Fountain's way of forcing a character cue, and Scenewise follows it: @MacKenzie on its own line, or @MacKenzie: We start at eight.

Rule 2: Spell each name the same way every time

An app can't know that NELL, NELLIE and MRS HARGREAVES are the same person. If your script switches between them, you'll get three characters. Either tidy the text before importing, or fix it afterwards: in Scenewise you can rename a character or merge two into one from the character list.

The opposite problem also happens. A capitalised word at the start of a line, like NOTE: or LATER:, can be mistaken for a name. Scenewise ignores the common ones, and you can mark any false character as "stage directions" with one tap.

Rule 3: Put stage directions in brackets

Brackets are the clearest signal that something isn't dialogue:

(NELL sits at the mirror, script in hand.)

ROSS: (taking the script) Top of the speech.

Bracketed text works on its own line or inside a speech. In Scenewise it's shown, but never read aloud and never hidden in the drills, so (taking the script) stays visible while Ross's words are spoken. Classic stage directions like Enter KIT., Exit. and Exeunt. on their own line are recognised without brackets.

In a screenplay, action lines without a name above them are already treated as description. Fountain's rule is that any paragraph that isn't something else is action. If an all-capitals action line is being read as a name, put ! in front of it (!LATER THAT NIGHT) to force it to be action.

Rule 4: Put scene headings on their own line

Scene headings split a script into scenes, which lets you rehearse one at a time and see a learnt score for each. These are recognised when they're on their own line:

  • SCENE 1, Scene 2: The garden, SCENE ONE
  • ACT I, Act 2, Scene 3
  • INT. KITCHEN - NIGHT, EXT. CAR PARK - DAY (screenplay sluglines, as Fountain defines them: lines beginning INT, EXT and similar)
  • Anything starting with a single full stop, like .THE WINGS, which is Fountain's way of forcing a heading

Put a blank line before and after each heading.

Rule 5: Let the title stand alone

A short line on its own at the very top is taken as the title, with or without a "by" line under it. Fountain title pages (Title: The Understudy) work too.

Clutter that's handled for you

Scripts exported from screenwriting software often carry page furniture. Page numbers, (MORE), (CONTINUED) and CONT'D markers are removed automatically. Fountain notes in double square brackets and "boneyard" text between /* and */ are ignored. Two-column dual dialogue is split into two separate speeches.

Running headers, like the play's title or a draft date at the top of every page, sometimes get attached to a speech. If you see one, remove it with Edit script text.

PDFs: text or scan?

This is the most common problem, and it can't be fixed by the app.

There are two very different kinds of PDF. One made from a word processor or screenwriting program stores the words as text, so you can search it, select it and copy it. A scanned PDF, made by scanning paper or saving a photo, is just a picture of each page with no text inside. ABBYY, which makes PDF software, describes the quick test: try to select or search for a word. If you can't, it's an image-only file.

The W3C's accessibility guidance makes the same point from another angle: screen readers can't read scanned pages either, because there are no characters to read, only images.

If your script is a scan:

  1. Ask for the original. Whoever sent it probably has the Word, Final Draft or text PDF it was made from.
  2. Run OCR (optical character recognition). Many PDF apps can do it, and it adds a hidden text layer to the scan. Check the result: OCR often mangles names, and a misread name becomes a new character.
  3. Paste the text in from another source, like the email or a shared document.

File types

Scenewise imports PDF (text, not scans), Word (.docx), Final Draft (.fdx), Fountain (.fountain) and plain text, or you can paste text straight in. Final Draft files are the most reliable, because they record which paragraph is a character, a line of dialogue or a direction. Old Word .doc files, Pages and RTF files need saving as .docx or PDF first.
